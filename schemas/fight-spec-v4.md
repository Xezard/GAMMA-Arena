# FightSpec v4

FightSpecV4 is the deterministic, side-effect-free description of one Arena
fight generated by catalog generator version 6, catalog revision 6, and layout
version 2.

| Field | Contract |
| --- | --- |
| schema_version | exactly 4 |
| generator_version | exactly 6 |
| catalog_revision | exactly 6 |
| layout_version | exactly 2 |
| session_seed | normalized Park-Miller state |
| fight_index | finite non-negative integer |
| fight_id | `ga-<seed>-<index>-g6-c6-l2` |
| actor | actor paths plus a validated budgeted loadout and actor-only bonus ammo |
| opponents | ordered human-only participants using unique resolved physical slots |
| diagnostic | stable `FightSpecV4` text |

Each opponent contains a dense logical slot, immutable physical spawn-slot ID,
resolved position and level/game vertex IDs, tactical route, equipment role,
profile/community, and validated loadout. Roles are `leader`, `primary`, or
`secondary`; leader and primary roles cannot receive pistols, while secondary
roles cannot receive primary firearms.

Actor loadout selection retains the approved weighted weapon-class/armor-class
pair algorithm. Candidate pairs are filtered by whether a concrete completion
fits the exact player budget (`player_loadout_budget`), then weighted by the
configured weapon-class and armor-class weights. Deterministic sorted concrete
candidates use the dedicated `actor_class_pair`, `actor_weapon`,
`actor_ammo_boxes`, and `actor_outfit` RNG streams; the knife uses
`actor_knife`.

After the actor weapon, budgeted base-ammo boxes, outfit, and loadout cost are
fixed, FightSpecV4 adds exactly one actor-only `bonus_ammo` box. Its category
draw uses `actor_bonus_ammo_category`: `standard` is 1..60, `special` is
61..75, and `armor_piercing` is 76..100. The compatible variant is chosen in
weapon-declared order with the independent `actor_bonus_ammo_section` stream.
If the requested category is unavailable, the bonus falls back to the weapon's
base standard ammo while retaining the requested category and resolving as
`standard`. Bonus ammo never changes the actor's loadout cost, affordability
candidates, or budget; opponents never carry a `bonus_ammo` field.

Enemy counts, budgets, roles, factions, and loadout selection are unchanged.
The deterministic per-slot budgets sum to at most the difficulty enemy budget.
The 70%-100% affordability band with a highest-affordable fallback applies
only to opponent equipment selection. Difficulty minimum primary shares and
the one-sniper cohort limit remain validation invariants.

The resolved layout is a required independent input. Generation and validation
never invent coordinates, reuse a physical slot, call engine APIs, or mutate
the game world. Tactical routes may be reused only after every native route has
been allocated once.

`stable_encode` includes physical position, vertex IDs, route, role, equipment,
costs, and only actor gear appends
`,bonus:<section>:<requested_category>:<resolved_category>:<boxes>`. Any
catalog, layout, role, routing, position, budget, ammo compatibility, or
ordering mismatch returns a structured validation error.
